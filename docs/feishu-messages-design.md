# 飞书消息：在胸牌上查看、朗读和语音回复（设计稿）

状态：调研完成，**还没有开始实现**。不用审批的简易版（读 Mac 系统通知）已经在 0.5.31 做好，见 [feishu-notify.md](feishu-notify.md)；本文是用飞书开放平台的完整版设计。调研时间是 2026-11-02，依据是飞书开放平台文档、官方 `larksuite/cli` 和 `oapi-sdk-python` 源码，以及 `lark-openapi-mcp` 的 README。标「未确认」的地方需要在真实租户里验证。

## 1. 目标

- 胸牌新增「飞书消息」页面：
  - 列出最近有新消息的会话，包括单聊和群聊。
  - 按确认可以展开阅读，也可以朗读出来。
- 有新消息时，胸牌在任何页面都弹出提示：谁发来的，加上前几个字。可以设置成只提醒单聊和 @我 的消息。
- 语音回复的流程：
  1. 长按上键开始说话。
  2. 胸牌显示识别出的文字。
  3. 按确认才以本人身份发出；不按就不发。

## 2. 调研结论

| 问题 | 结论 | 依据 |
| --- | --- | --- |
| 能不能读本人与别人的私聊 | **能**，但必须用用户身份（user_access_token）。机器人身份读不到 | `GET /im/v1/messages` 支持 user token。单聊需要 `im:message.p2p_msg:get_as_user`，群聊需要 `im:message.group_msg:get_as_user`，另外还要 `im:message` 或 `im:message:readonly`。官方 CLI 的 `+chat-messages-list --user-id` 只能用用户身份 |
| 列出会话 | 用户身份可以列出单聊和群聊，并按最近活跃排序 | 官方 CLI 的 `+chat-list --as user --types p2p,group`。公开文档写的是“不含单聊”，`types` 参数在文档里**未确认** |
| 实时推送 | **没有**用户身份的消息事件。`im.message.receive_v1` 只覆盖发给机器人的消息 | 官方 CLI 的 IM 事件全部是 `AuthTypes: bot` |
| 结论 | **只能轮询** | 消息接口限频 1000 次/分钟、50 次/秒；每 10–15 秒查一轮大约 20–30 次/分钟，远低于上限 |
| 以本人身份发送和回复 | 可以。`POST /im/v1/messages` 和 `/messages/{id}/reply`，权限 `im:message.send_as_user` | 同一个会话 5 QPS；`uuid` 字段可在 1 小时内去重 |
| 发语音条 | 先上传 opus 文件（`/im/v1/files`），再发 `msg_type=audio`。以用户身份能不能发**未确认** | 第一版只发文字 |
| 标记已读、未读数 | **没有接口** | 只能查已读状态（`/im/v1/messages/read_status`，用户身份）。胸牌上的“已读”只记在本地，手机上仍然显示未读 |
| 用户授权 | 授权码加 PKCE，`offline_access` 才会拿到 refresh_token。官方 MCP 使用 `http://localhost:3000/callback` | access_token 约 2 小时；refresh_token 约 7 天，而且**只能用一次**；满 365 天需要重新授权 |
| 应用类型 | 企业自建应用。正式版本的用户权限要**企业管理员审批**；测试企业里可以免审 | 个人版账号能不能建应用**未确认** |
| 国际版 Lark | 域名换成 `open.larksuite.com` 和 `accounts.larksuite.com`，SDK 用 `lark.LARK_DOMAIN` | |

可以复用的开源项目（都是 MIT 许可）：

- `larksuite/cli`：已经做好设备码登录、钥匙串存 token、单聊会话解析、消息转成可读文本、以用户身份发送。
- `larksuite/oapi-sdk-python`（`lark-oapi`）。
- `larksuite/lark-openapi-mcp`。

## 3. 架构

```
飞书开放平台 ⇄ 电脑助手（Python，保管 token、轮询、转文本、限频）⇄ USB/蓝牙 ⇄ 胸牌（列表、提醒、朗读、录音）
```

- **token 只放在电脑助手上，不放进胸牌。**
  - 原因一：C3 内存紧张，而且 HTTPS 加 OAuth 刷新逻辑不适合放在胸牌上。
  - 原因二：胸牌离身就可能被别人拿到。
  - Mac 存在钥匙串里；Windows 用 DPAPI（或者先用 0600 权限的文件）。
- 这个页面属于电脑页面，和「电脑状态」「AI 额度」「离座锁屏」同一类：`needsComputer(App::Feishu)` 返回 true。
  - 胸牌发出 `{app, operation, generation}` 请求。
  - 助手在 `passport_services.response()` 里返回 `state/value/lines`。
  - 有新数据时，用 `push(state, context)` 主动推给胸牌，写法和 `guard_loop` 一样。
- **助手接飞书有两条路，推荐 A：**
  - **A. 直接用 `lark-oapi` SDK 写约 300 行。** 授权、轮询、发送都自己控制，打包进助手也简单。
  - **B. 调用官方 `lark-cli`。** 省掉登录和内容解析，但要额外装 Node 版 CLI，而且 CLI 和助手会**争用同一个只能用一次的 refresh_token**。只适合原型阶段。
- **轮询流程：**
  1. 每 15 秒拉一次会话列表，按 `active_time` 排序。
  2. 只对活跃时间变了的会话，用 `start_time` 拉新消息，按 `message_id` 去重。
  3. 自己发的消息不提醒。
  4. 遇到 429 时按 `x-ogw-ratelimit-reset` 退避。
  5. 胸牌上打开这个页面时，提速到每 5 秒一轮。
- **内容转文本：**
  - `text` 类型：把 `@_user_N` 换成 `mentions` 里的名字。
  - `post` 类型：逐段拼接，图片写成「[图片]」，代码块写成「[代码]」。
  - 其他类型写成「[文件]」「[卡片]」等。
  - 每条最多 600 字。胸牌单条消息上限 2 KiB，蓝牙缓冲 2304 字节。
- **朗读：** 胸牌直接用已有的百度 TTS（中英翻译页面里的 `say()`）读出「张三说：……」。不需要助手合成音频。
- **听写：** 复用语音笔记用的第二个小智身份（`transcribing()`）。只取识别出的文字，不进入小智聊天记录。

## 4. 胸牌上的交互（App::Feishu，「工具 · 设置」页已满，放进「电脑 · 时间」或新的一页）

| 状态 | 上/下 | 确认 | 长按上 | 长按下 |
| --- | --- | --- | --- | --- |
| 会话列表 | 选择会话 | 打开 | 刷新 | 只看 @我 / 全部 |
| 会话内（最近 6 条，最新的在下面） | 滚动 | 朗读这条 | 语音回复这条 | 返回列表 |
| 录音中 | — | 结束录音 | — | — |
| 确认发送（显示识别出的文字） | — | **发送** | 重说 | 放弃 |

- 提醒：在任意页面，屏幕顶部滑出一行「飞书 · 张三：明天十点开会…」，保持 5 秒。
  - 在提醒期间长按确认，直接跳到这个会话。
  - 可以复用已有的 `notices` 通知队列和亮屏逻辑。
- 系统设置里的新开关：
  - 「飞书提醒」：关 / 仅单聊和 @我 / 全部。
  - 「自动朗读」：默认关闭，避免私聊内容被外放。
- 电脑助手的设置网页新增「飞书」一节：
  - 「登录飞书」按钮：打开浏览器授权，回调地址是 `http://localhost:8768/feishu/callback`。
  - 显示当前登录的账号，可以退出登录。
  - 免打扰会话列表、轮询间隔。

## 5. 数据和协议（草案）

- `operation`：`enter`、`list`、`open:<chat>`、`more`、`reply:<message_id>:<text>`、`mode:at|all`。
- 返回的 `lines`（4×160 字节）不够用，所以和财经新闻页一样，用 `page` union 放一个 `FeishuView`，约 4.5 KB：
  - 最近 8 个会话：名字 24 字节、未读数、最后一条 60 字节。
  - 打开的会话里 6 条消息：发送人 16 字节、时间、正文 600 字节。
  - 会话和消息 ID 不发给胸牌，只发助手分配的短序号，助手自己保存对应关系。
- 发送一定要等胸牌按确认之后才发。助手生成 `uuid` 防止重复发送，发送结果回传给胸牌显示「已发送」或错误原因。

## 6. 分期

1. **P1 只读**（约 2–3 天）：
   - 助手完成授权、轮询和内容转文本。
   - 胸牌做列表、会话页、朗读和任意页面的提醒。
   - 先在自己建的测试企业里免审跑通。
2. **P2 语音回复**（约 1–2 天）：听写、确认、以用户身份回复。
3. **P3（可选）**：
   - 「@我」优先：用 `search:message` 的 `at_chatter_ids` 过滤。
   - 免打扰时段。
   - 语音条回复：要先确认用户身份能不能发 audio。
   - 国际版 Lark。

## 7. 风险和要先确认的事

1. **公司管理员是否批准** `get_as_user` 和 `send_as_user`。这是最大的风险，审批不通过就只能在自建的测试企业里用。开启了对外共享的应用会报 231204。
2. 用户身份读群消息时，是否也受“机器人必须在群里”（230002）限制：**未确认**，需要实测。
3. refresh_token 只能用一次：同一时间只能有一个进程负责刷新。刷新失败时提示重新登录，不要死循环重试。
4. 没有标记已读的接口，手机上的未读数不会因为在胸牌上看过而减少。
5. 语音识别出错会以本人名义发出去，所以一定要有确认这一步；也不做“自动回复”。
6. 隐私：私聊内容默认不外放；胸牌锁屏或离座时不显示正文。
7. 月度调用配额：**未确认**。官方页面没写，按每分钟 20–30 次算，一天约 3–4 万次。
