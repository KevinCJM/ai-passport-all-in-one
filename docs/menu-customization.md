# 菜单自定义

开发版本：0.5.26（菜单自定义从0.5.22加入；0.5.26 起不分页可选九宫格或紧凑列表）。Mac 助手从 0.1.2-preview 起内置菜单编辑器。手机配置网页和 Mac 助手共用 `scripts/passport_menu.js`；设置保存在胸牌，首次升级默认显示原来的43项。

## 操作

1. 手机进入胸牌「系统设置 → WiFi 配置 → 添加 WiFi」，加入屏幕上的热点，打开 `http://192.168.8.1` 的「菜单」。也可在已连接胸牌的 Mac 小助手点「网页设置」或菜单栏「菜单自定义…」。
2. 勾选功能，选择显示方式：原有分类、自定义分页、不分页 · 九宫格、不分页 · 紧凑列表。可拖动，或按上移／下移。自定义分页通过每项右边的下拉框决定功能在哪页，页面名称1～8字，最多8页、每页9项。两种不分页方式共用一份顺序，另外两种各有自己的顺序。
3. 查看排列预览，点击「保存到胸牌」。显示成功表示胸牌已写入并应用。重新读取会丢弃当前未保存的编辑；恢复默认后也要保存。

原有分类允许调整分类顺序及分类内顺序。不分页 · 九宫格把选中的功能按顺序每9个一屏，标题为「全部功能」，右上角显示屏号；不分页 · 紧凑列表每屏7行（小图标＋名称），右上角显示选中项序号／总数，长按上下快移7项。分页模式跳过空页，右上角显示页码；九宫格和分页模式长按上下切换页面。功能图标、色彩及三个按键的进入／返回方式保持原风格。

系统设置可以移动但不能隐藏；删除含系统设置的页前先移动它。删除其他页面时，其中的功能回到未显示状态。隐藏功能保留数据，语音跳转及自动提醒不受菜单布局限制；配置不会中断正在使用的功能。

恢复显示功能时，原自定义页满后会选择其他空位，必要时自动补充新页；因此在连续菜单选择「全部显示」不会受之前自定义页数量限制。

## 固件契约

- `App` 协议编号和 `kFunctions` 原始目录保持稳定。`selection()` 仍为完整目录索引，以兼容现有状态接口；统一用 `selectedApp()` 获取选中目标，避免音频准备与图标排列不一致。
- `MenuLayout` 是481字节、全字节字段的版本化记录：版本、模式、目录数量、自定义页数；8字节隐藏位图；5字节原分类顺序；三份64字节 App ID 顺序；64字节 App ID 到自定义页的分配；8字节页顺序；八份25字节 UTF-8 页名。
- 模式值0／1／2／3分别表示分类／不分页九宫格／自定义／紧凑列表。紧凑列表没有自己的顺序字段，使用模式1的顺序（`MenuLayout::orderOf`）；0.5.25及更早的固件拒绝模式3。字段偏移依次为0、1、2、3、4、12、17、209、273、281。未使用的顺序位置为255，页名必须以NUL结束、最多8个Unicode字符且无控制字符。
- `MenuView` 为83字节，只保存可见目录索引、有效分页边界和类别。不分页九宫格在 `MenuView` 里按9个一屏切分；紧凑列表把同样九个 LVGL 单元改排成7行，按可视窗口滚动，功能数量不会增加控件数量。
- 新配置用独立 NVS 键 `suite_system/menu_v1`，不修改 `config_v1`。缺失或无效时回退默认菜单；旧目录记录追加新 App 并默认显示。相同配置不会重复写入。
- `MenuService` 只保留一个待提交布局，主循环持锁完成校验、NVS提交、视图替换及结果确认。HTTP任务及BLE回调不直接操作LVGL。保存失败时保留原布局；物理按键上下文包含菜单修订，丢弃布局变更前的旧按键。

## 配置接口

设备 HTTP 和已授权 BLE RPC 使用相同路径：

- `GET /menu`：返回 `layout`（481字节记录的Base64）、`revision`、`pending`、`done`、`result`。
- `GET /menu/catalog?group=0` 到 `4`：返回对应分类名称和功能的稳定ID、菜单名称。分类分批读取，响应适配现有2304字节BLE缓冲。
- `POST /menu`：`{"layout":"…","revision":123}`。成功接收返回 `{"queued":true,"ticket":…}`；客户端继续读取，等 `done` 与ticket一致、`result=0`且布局一致才确认成功。修订冲突或已有待保存请求返回409，无效布局返回400。

API复用现有设备所有者认证及配网热点访问范围；网页写入保留来源检查。Mac 的 `/api/menu` 和分类接口经已配对设备的USB／BLE传输转发。启动修订使用随机值，防止设备重启后旧网页直接覆盖新设置。源码内置同一份离线JS，无外部前端依赖。

## 验证

```bash
python3 tests/test_passport_menu.py -v
bash scripts/build_passport_suite.sh
python3 scripts/test_passport_menu_sim.py
bash scripts/build_passport_suite.sh connectivity
python3 scripts/test_passport_menu_http.py
bash scripts/build_passport_suite.sh device
```

宿主测试需要C++20编译器和Node.js；固件构建需要ESP-IDF 6.1；仿真脚本使用本机 `~/.local/share/esp32-agent/bin/esp-emu`，只写临时虚拟Flash。产物在 `releases/menu-customization-test/` 和 `releases/menu-customization-http-test/`，包括完整帧PNG、运行日志、校验报告及冷启动结果。

覆盖默认布局、随机排列、异常数据、连续滚动、功能进入与返回、隐藏功能的直接跳转、页名与页顺序、只保留系统设置、NVS恢复、实际HTTP保存与冲突、USB／BLE助手路由。模拟器截图来自C3内的LVGL实际像素；实机射频、真实音频和物理按键手感仍需设备验收。
